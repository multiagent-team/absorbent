# Absorbent

Превращает запись онлайн-лекции (скринкаст `*.mkv`/`*.mp4` или аудиофайл) в
качественный конспект в Markdown: структурированный текст по транскрипту,
слайды-иллюстрации из видео и формулы в LaTeX. Готовый `notes.md` рядом с
исходником, изображения — в соседнем каталоге `images/`, документ можно
сразу отдавать в pandoc.

Конвейер устроен так:

1. из видео через ffmpeg извлекаются кадры с частотой `--fps` (по умолчанию
   один кадр в секунду); вход без видеопотока (аудиофайл) проверяется
   `ffprobe` и пропускает этот и следующий этап;
2. кадры дедуплицируются по перцептивному хешу (pHash): остаются только
   значимые смены картинки — шум мерцания курсора отсекается;
3. речь распознаётся в транскрипт с таймкодами: локально через Whisper,
   локально через Voxtral Realtime на vLLM или облачно через Voxtral
   (Mistral) с диаризацией спикеров;
4. vision-модель описывает каждый ключевой кадр, получая на вход картинку,
   её таймкод и фрагмент транскрипта вокруг этого момента;
5. текстовая LLM синтезирует полный Markdown-конспект по транскрипту и
   описаниям кадров, вставляя изображения `![подпись](images/frame_....jpg)`
   ровно с теми именами файлов, что реально лежат на диске;
6. постпроцессинг: таблицы notes.md выравниваются скриптом
   `fmt-md-tables`, затем pandoc собирает самодостаточный `notes.html`
   (CSS-тема github-markdown, формулы MathML) и `notes.pdf` через движок
   lualatex со шрифтами DejaVu.

Провайдеры и модели задаются в одном YAML-файле; ключи API берутся из
переменных окружения; конкретная модель каждого этапа выбирается флагом
командной строки.

## Установка

Требуется [uv](https://docs.astral.sh/uv/), `ffmpeg` и `ffprobe` в PATH
(пакет `ffmpeg` в Arch Linux). CUDA-видеокарта необязательна — нужна только
для локального Whisper; без неё Whisper работает на CPU медленнее.

Для локального бэкенда `voxtral-realtime` (веса Voxtral Realtime на своём
GPU, без аккаунта Mistral) нужен установленный vLLM — отдельным
инструментом, чтобы не тянуть его зависимости в окружение проекта:

```bash
uv tool install "vllm[audio]"
```

Absorbent сам запускает `vllm serve` и гасит его после прогона, поэтому
отдельно поднимать сервер не нужно. Требуется видеокарта с запасом памяти
(веса модели — ~9 ГБ); облачный `voxtral-transcribe-2` и Whisper в vLLM не
нуждаются.

Для постпроцессинга (этап 6) нужны внешние инструменты:
`fmt-md-tables` (выравнивание таблиц), `pandoc`, движок `lualatex` и
шрифты DejaVu (кириллица). Без них конвейер работает до синтеза
notes.md; HTML/PDF отключаются флагом `--skip-render`.

```bash
uv sync
```

## Конфигурация

Конфигурация ищется в порядке: путь из `--config` → `./config.yaml` →
`~/.config/absorbent/config.yaml`. В репозитории лежит рабочий `config.yaml`
со схемой:

```yaml
providers:
  deepseek:                # OpenAI-совместимый провайдер
    base_url: https://api.deepseek.com
    api_key_env: DEEPSEEK_API_KEY   # имя переменной окружения с ключом
  llama-swap:              # локальный сервер (llama-swap на 127.0.0.1:12434)
    base_url: http://127.0.0.1:12434/v1
    api_key_env: ""        # пусто -> запросы без заголовка Authorization
  vllm-voxtral:            # локальный vLLM с Voxtral Realtime
    base_url: http://127.0.0.1:12435
    api_key_env: ""
    vllm_bin: ~/.local/bin/vllm   # путь к бинарю vLLM
    gpu: "1"               # CUDA_VISIBLE_DEVICES для автозапуска ("" — не задавать)
    autostart: true        # поднять сервер, если порт закрыт

stt:                       # распознавание речи
  whisper-turbo:           # локальный Whisper (по умолчанию)
    backend: whisper
    whisper_model: turbo
    default: true
  voxtral-transcribe-2:    # облачный Voxtral (Mistral), нужен MISTRAL_API_KEY
    backend: voxtral
    provider: mistral
    model: voxtral-mini-latest
  voxtral-realtime:        # локальные веса Voxtral Realtime через vLLM
    backend: voxtral-realtime
    provider: vllm-voxtral
    model: mistralai/Voxtral-Mini-4B-Realtime-2602
    chunk_seconds: 300     # длина фрагмента нарезки по паузам

vision:                    # описание кадров
  deepseek-v4-flash-vision-exp:
    provider: deepseek
    default: true

llm:                       # синтез конспекта
  deepseek-v4-flash:
    provider: deepseek
    default: true
```

Правила:

- `default: true` ровно в одной модели каждой категории (`stt`, `vision`,
  `llm`) задаёт модель по умолчанию;
- ключ API провайдера читается из переменной окружения, имя которой
  указано в `api_key_env`; пустое значение — запросы без авторизации
  (локальные серверы);
- если переменная задана в конфиге, но отсутствует в окружении, программа
  останавливается с ошибкой `missing env var <имя>`;
- у моделей `stt` с `backend: whisper` поле `whisper_model` задаёт модель
  openai-whisper; у облачных бэкендов поле `model` — id модели в API;
- у моделей `stt` с `backend: voxtral-realtime` поле `chunk_seconds` задаёт
  длину фрагмента нарезки (секунды, по умолчанию 300); окно модели
  считается из него автоматически;
- поля `vllm_bin`, `gpu` и `autostart` относятся только к провайдерам,
  которые Absorbent поднимает сам; `~` в `vllm_bin` раскрывается до пути
  домашнего каталога; при автозапуске Absorbent выставляет
  `CUDA_DEVICE_ORDER=PCI_BUS_ID`, поэтому значение `gpu` указывает на ту же
  карту, что и индекс в `nvidia-smi` (без этого CUDA сортирует устройства по
  скорости и номер означает другую карту).

Необходимые переменные окружения:

- `DEEPSEEK_API_KEY` — для облачных моделей DeepSeek (vision/llm по
  умолчанию);
- `MISTRAL_API_KEY` — только если выбран `--stt voxtral-transcribe-2`;
- для `--stt voxtral-realtime` переменные окружения не нужны: сервер
  локальный.

## Использование

```bash
uv run absorbent lecture.mkv
```

Флаги:

| Флаг                        | Значение по умолчанию         | Описание                                                                                                                               |
|-----------------------------|-------------------------------|----------------------------------------------------------------------------------------------------------------------------------------|
| `input`                     | —                             | путь к медиафайлу или директории (обрабатываются все файлы `.mp4 .mkv .webm .avi .mov .mp3 .wav .flac .ogg .m4a .opus`)                |
| `--config PATH`             | поиск по умолчанию            | путь к YAML-конфигурации                                                                                                               |
| `--stt NAME`                | дефолт из конфига             | модель распознавания речи                                                                                                              |
| `--vision-model NAME`       | дефолт из конфига             | модель описания кадров                                                                                                                 |
| `--llm-model NAME`          | дефолт из конфига             | модель синтеза конспекта                                                                                                               |
| `--language {ru,en,auto}`   | `auto`                        | подсказка языка распознавания речи; `ru/en` форсируют весь файл как один язык, `auto` — детекция (для двуязычных лекций всегда `auto`) |
| `--output-language {ru,en}` | `ru`                          | язык итогового конспекта и промптов; дословные RU/EN-фразы лекции сохраняются в оригинале                                              |
| `--fps N`                   | `1`                           | частота извлечения кадров                                                                                                              |
| `--hash-threshold N`        | `10`                          | порог pHash-расстояния для дедупликации, 0–64                                                                                          |
| `--output-dir DIR`          | `<имя_файла>/` рядом с входом | каталог результата                                                                                                                     |
| `--flat`                    | —                             | результат и сырой транскрипт рядом с входным файлом (`<имя>.md`, `<имя>.json`, `<имя>.images/`), кэш — в `<каталог>/.absorbent/<имя>/` |
| `--force`                   | —                             | игнорировать кэш и перезапустить все этапы                                                                                             |
| `--skip-stt`                | —                             | пропустить распознавание речи                                                                                                          |
| `--skip-frames`             | —                             | пропустить извлечение и дедупликацию кадров                                                                                            |
| `--skip-describe`           | —                             | пропустить описание кадров                                                                                                             |
| `--skip-synthesize`         | —                             | пропустить синтез Markdown                                                                                                             |
| `--skip-render`             | —                             | пропустить постпроцессинг (таблицы, HTML, PDF)                                                                                         |

Неизвестное имя модели (`--stt`, `--vision-model`, `--llm-model`) печатает
список допустимых имён в этой категории и завершается с кодом 2.

Язык лекции и язык конспекта — независимые настройки. Лекции могут быть
двуязычными (например, речь почти целиком на английском с русскими
вставками): whisper возвращает один язык на весь файл, поэтому для таких
записей `--language` следует оставлять в `auto`. `--output-language`
определяет, на каком языке модель пишет описания кадров и конспект, а
дословные фразы и термины из транскрипта на другом языке (например,
русские цитаты в английской лекции) сохраняются в оригинале.

Если кадров вышло слишком много или слишком мало — перенастройте
`--hash-threshold` (меньше — больше кадров) или `--fps`. Кадры кэшируются,
повторный прогон без `--force` не переизвлекает видео.

## Локальный Voxtral Realtime

```bash
uv run absorbent --stt voxtral-realtime lecture.mp4
```

Backend `voxtral-realtime` гоняет открытые веса
`mistralai/Voxtral-Mini-4B-Realtime-2602` на своём GPU через vLLM: аккаунт
Mistral и `MISTRAL_API_KEY` не нужны.

Что происходит по шагам:

1. аудио вытаскивается в PCM s16le 16 кГц моно (кэш `audio.s16le`);
2. `silencedetect` находит паузы; запись режется на фрагменты по
   `chunk_seconds` секунд, причём рез ставится на ближайшую паузу, если она
   есть рядом с целью, иначе — по времени;
3. сервер vLLM, если порт закрыт, поднимается автоматически
   (`vllm serve … --compilation_config '{"cudagraph_mode": "PIECEWISE"}'`, как
   рекомендует карточка модели) и гасится после прогона; готовность
   проверяется опросом `/v1/models`, лог пишется в
   `${XDG_CACHE_HOME:-~/.cache}/absorbent/vllm.log`;
4. каждый фрагмент уходит по протоколу `/v1/realtime` (WebSocket,
   base64-PCM16) и возвращает текст; при ошибке фрагмента делается одна
   повторная попытка, затем фрагмент пропускается с предупреждением.

Ограничения бэкенда, о которых стоит знать:

- **таймкодов и спикеров нет**: сегменты `transcript.json` получают границы
  фрагментов (start/end = резы по паузам), а `speaker` всегда `null` —
  диаризация есть только у облачного `voxtral-transcribe-2`;
- **подсказка языка не передаётся**: `--language ru|en` для этого бэкенда
  игнорируется с предупреждением, язык модель определяет сама
  (`--output-language` при этом работает как обычно);
- первый запуск скачивает ~9 ГБ весов и тратит ~1 минуту на старт сервера
  (ожидание готовности — до 15 минут);
- значение `chunk_seconds` влияет на окно модели: Absorbent считает
  `max_model_len` из него сам, поэтому дробить запись мельче не нужно;
- модель потоковая: один текстовый токен на 80 мс аудио, поэтому один поток
  распознаётся примерно вдвое-втрое быстрее реального времени (около 25
  минут на час аудио). Whisper turbo на той же машине быстрее на порядок —
  см. `STT_COMPARISON.md`.

Если сервер уже поднят вручную (например, `vllm serve` в другом терминале),
Absorbent это увидит и переиспользует: повторный запуск пропускается, а
чужой сервис на том же порту даёт понятную ошибку вместо тихой поломки.

## Выходные файлы

Для входа `Lecture.mkv` (каталог результата по умолчанию — `Lecture/`):

```
Lecture/
  notes.md                  # итоговый конспект Markdown
  notes.html                # самодостаточный HTML (css и кадры встроены)
  notes.pdf                 # PDF через lualatex
  images/                   # ключевые кадры, на которые ссылается notes.md
    frame_HH_MM_SS.jpg
  .absorbent/               # кэш промежуточных результатов
    transcript.json         # [{start, end, text, speaker}]
    audio.wav               # извлечённое аудио (только voxtral)
    language.txt            # детектированный язык
    frames/                 # все извлечённые кадры до дедупликации
    keyframes.json          # отобранные кадры: image/seconds/timestamp
    descriptions.json       # описания кадров vision-моделью
```

`notes.md`, `notes.html`, `notes.pdf` и `images/` — результат; всё под
`.absorbent/` можно удалять без потери результата (кэш лишь ускоряет
повторные прогоны).

### Плоский режим (--flat)

Флаг `--flat` кладёт результат рядом с медиафайлом, без каталога `<имя>/`:

```
Lecture.mp4
Lecture.md                  # итоговый конспект Markdown
Lecture.json                # сырой транскрипт [{start, end, text, speaker}]
Lecture.html                # самодостаточный HTML
Lecture.pdf                 # PDF через lualatex
Lecture.images/             # ключевые кадры, на которые ссылается Lecture.md
  frame_HH_MM_SS.jpg
.absorbent/
  Lecture/                  # кэш промежуточных результатов
    language.txt
    frames/
    keyframes.json
    descriptions.json
```

Ссылки на изображения в конспекте получают префикс `<имя>.images/`, поэтому
относительные пути остаются корректными; `--output-dir` и в этом режиме
задаёт каталог результата, а кэш всё равно ложится в
`<каталог входа>/.absorbent/<имя>/`.

### Вход без видеопотока

Если во входном файле нет видеопотока (mp3, m4a, wav), этапы извлечения и
дедупликации кадров пропускаются: конвейер печатает «кадров нет (аудио без
видеопотока)» и собирает конспект только по транскрипту, без иллюстраций.
Проверка выполняется `ffprobe` до запуска ffmpeg, поэтому аудиофайл не
завершается ошибкой извлечения кадров.

## Постпроцессинг

После синтеза конвейер автоматически:
1. выравнивает таблицы `notes.md` внешним скриптом `fmt-md-tables`;
2. собирает самодостаточный `notes.html` через
   `pandoc --standalone --embed-resources` — CSS-тема github-markdown
   (файл в `src/absorbent/assets/github-markdown.css`, лицензия MIT,
   sindresorhus), изображения встроены как data-URI, формулы — MathML;
3. собирает `notes.pdf` через `pandoc --pdf-engine=lualatex` со шрифтами
   DejaVu и полями 2 см; первый заголовок notes.md становится title.

HTML/PDF можно отключить флагом `--skip-render` (например, когда pandoc
или lualatex не установлены).

## Разработка

- Код — Python 3.13+, пакет в `src/absorbent/`, каждый этап — отдельный
  модуль (`extract.py`, `dedup.py`, `transcribe.py`, `describe.py`,
  `synthesize.py`, `render.py`), оркестрация — в `pipeline.py`;
  локальный бэкенд Voxtral Realtime (сервер vLLM, WebSocket-клиент и
  нарезка аудио) — в `realtime.py`.
- Соглашения по комментариям и коммитам — в `AGENTS.md`.
- Отложенные идеи — в `BACKLOG.md`.
- Тесты: `uv run pytest --cov` (покрытие ветвей 100%, порог задан в
  `pyproject.toml` через `fail_under = 100`). Интеграционный тест
  требует ffmpeg/ffprobe в PATH и пропускается без них.
- Отложенные идеи — в `BACKLOG.md`.
